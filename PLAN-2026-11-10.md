# Improvement plan, 2026-11-10 (long-context work only)

Scope: agent wall time on sessions of 32K–150K tokens. Short-context speed is not a goal. Each item has a gate; an
item ships only when its gate passes, and every GPU run writes its own log (summary.md) so nobody has to watch it.
Baselines: `splash/SESSIONS-2026-11-10.md` (real sessions), `splash/dev-dspine/dev/ab-round1` (drafter),
`splash/ANALYSIS.md` (cost curves: prefill 2.45 + 0.0245·ctxK ms/token, decode 87 + 0.45·ctxK ms/cycle).

## How every item is checked
| check | tool | when |
|---|---|---|
| Unattended run with a log | `scripts/auto-tests.sh [--gpu] [--quick]` → `logs/auto-tests/<ts>/summary.md` | every GPU item; one GPU track at a time |
| Real-session accounting | `splash/tools/park_session_steps.py <session>` (per-step prompt, cached, TTFT, decode) and `session_tool_share.py` | after any harness change: one long real session, compared with SESSIONS-2026-11-10.md |
| Long-context replay benchmark | `splash/tools/park_long.py` (70K prefix + N agent-shaped turns, byte-stable) | every engine item: A-B-B-A, flag off/on, TTFT and ms/cycle per turn |
| Exactness | digests, near-tie margins, dist/fruit tests, oracle logits (as in ab_dspine.sh / park_ab.sh) | every engine item |
| Accuracy | eval t1–t6 (`eval/run_eval.py`) and the platform bench (`workspace/platform-bench/run_bench.py`) | before anything becomes a default |
| Rules | AC power, GPU lock, Defender gate, backup + patch 0003 re-export, SPEED_LOG entry | always |

## D. Order and cost
1. A1 finish (GPU, waiter) → A2 (your next real session, free) → B1/B3 (bench runs, ~2 h GPU).
2. C1 profile (20 min GPU) → decide C1 vs C2 first by measured share.
3. C3 round 2 (half a day GPU) → C4/C5 after.
Every step: agents log to files; no polling; results read once at the end. Keep one GPU track at a time: the
2026-11-09 three-track attempt finished nothing because of lock contention.

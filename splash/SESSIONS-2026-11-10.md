# Long-context session analysis, 2026-11-09/10 (3 web-UI sessions, cross-repo work)

**Sources:**
- dsh sessions, matched step by step with Splash's per-cycle log (`logs/splash/steps.jsonl`).
- One session ran on DFlash2; two ran on DSpine (`SPLASH_SRC=splash/dev-dspine SPLASH_DRAFTER=dspine`).
- dsh window 151,537 tokens; compaction at 80% (~121K).

Company-specific content (prompts, file names) is left out; the raw join is in the session scratchpad.

## Where the time went
| | DFlash2 period | DSpine period |
|---|---|---|
| Splash prefill time | 941 s | **1,496 s** |
| Splash decode time | 1,539 s | 821 s |

**At long context, prefill (prompt processing) cost more than generation** in the DSpine sessions: 65% of model time.
It came from three things.

1. **Tool-result pruner re-prefills.**
   - At about 80% context the pruner rewrote an old tool result, which invalidated the prompt cache from that
     point on.
   - The cost was one 73.7K-token re-prefill (**246 s**) and one 78.4K-token re-prefill (**316 s**).
   - The second was immediately followed by compaction (**390 s**).
   - The rewritten result was a single whole-file `read` of 71K chars.
   - The web UI uses the `lean` preset, so the headless fix from 2026-10-27 never applied to it.
2. **Per-step prefill at long context is slow.**
   - Throughput: ~290 tok/s at 50K, ~195 tok/s at 100–120K. So a step that adds 4K tokens of tool output costs
     about 21 s of prefill before decoding starts.
   - At 100K, typical steps were 3–7 s of decode against 5–21 s of prefill.
3. **Many tiny steps.** One research turn took 36 steps of `ls`/`head`/`wc`/whole-file `read` before the user
   stepped in, with the code graph available but unused. Each step pays the full long-context prefill and a reasoning
   preamble.

## Drift and behaviour patterns
- **Over-reach:** the agent edited files when the user wanted only a display change, and the user aborted twice.
  Long reasoning steps came with it: 190–208 s steps with 22–27K reasoning chars.
- **Shell navigation instead of the graph:** the agent chained `ls`, `head`, `wc` and `cat` even with
  `mcp__cbm__*` available. It used the graph only after the user said so; then steps became small (3–27 s).
- **Unindexed repo:** the research spanned a repository that was not in the CBM index, so every lookup there fell
  back to whole-file reads.
- **Unknown slash command:** `/archify` cost 9 steps of searching before the user aborted. It is now installed as the
  `@tt-a1i/archify-dsh` plugin.
- **Per-repo CLAUDE.md:** reminders are injected as the agent enters each repo, adding tokens mid-session. This is
  expected; no change.

## Remedies applied 2026-11-10 (effective in new web sessions: restart `scripts/work`)
| # | change | where | expected effect |

| 1 | tool-result pruner effectively off (threshold 10⁹ chars) | `config/dsh/presets/lean/agent.cordis.yml` | removes the 250–320 s re-prefills; compaction alone manages context |

## Next engine levers (prefill now dominates at long context)
1. **Park lane:** keep a cached state after the model's own reply, so its last output is not prefilled again. That is
   38–44% of per-step prefill tokens (ANALYSIS.md section 6).
2. **Long-context prefill attention:** attention is about half of prefill time per token at 100K. Try a faster prefill
   attention kernel (tiling, int8 Q·K).
3. **Verify all six remedies on a long session.** Track TTFT per step and total prefill seconds against this file's
   numbers. `scripts/auto-tests.sh` can host the job once a long-session replay exists.
